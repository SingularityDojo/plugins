# plan-md — テーマの計画と時間の記録

テーマを1つ始めるときに `plan.md` を作り、テーマが終わるまで更新し続ける。テーマの振り返り（report.md）は `report` スキルが、この plan.md を読んで書く。

## 手順

### 1. テーマのディレクトリを決める

- 今日の日付ディレクトリは `~/playground/$(date +%Y/%Y%m/%Y%m%d)`。なければ `mkdir -p` で作る
- ユーザーが送った言葉（例: `$dojo:plan-md 自己紹介を3行で書く`）がゴール。ざっくりでよい
- ゴールが、今日の日付ディレクトリにある既存のテーマの続きなら、そのテーマを再開する。plan.md は作り直さず、時間の記録に「再開」の行を足す。続きかどうか分からないときは、既存のテーマを挙げて聞く
- 新しいテーマなら、ゴールからテーマ名を決める。英小文字とハイフンで、何をしたか後から分かる名前にする（例: 「自己紹介を3行で書く」→ `self-intro`）。名前のためだけに質問はしない

### 2. plan.md を書く

時刻は必ず `date '+%Y-%m-%d %H:%M'` で取る。推測した時刻は書かない。

```markdown
# <テーマを1文で>

## ゴール

<何をするか・なぜやるかを1〜2文で>

**完了条件**: <終わったと確かめられる状態>

## 手順

1. [ ] <手順>
2. [ ] <手順>
3. [ ] <完了条件を確かめる>

## 気づいたこと

## 時間の記録

| 時刻 | 区切り | メモ |
|------|--------|------|
| YYYY-MM-DD HH:MM | 開始 | 「<ユーザーが送った言葉>」 |
| YYYY-MM-DD HH:MM | 手順1完了 (6m) | <何をしたか> |    ← 2行目からは、前の行からの経過を (Nm) で書く
```

- 完了条件は、ユーザーが自分で確かめられる状態にする（例: 「self-intro.md に3行ある」）
- 手順の最後に、完了条件をどう確かめるかを置く
- 手順には番号を振る。会話で「手順2」と指せるようにするため
- 書いたら、ゴール・完了条件・手順を短く見せて、ずれていないか聞く

### 3. 作業中に更新する

区切りが来るたびに、頼まれなくても plan.md を更新する。区切りの例: 手順が終わった、方針を変えた、中断した、再開した。

- `date '+%Y-%m-%d %H:%M'` で時刻を取り、時間の記録に1行足す。区切りの後ろに、前の行からの経過を分で書く（例: `手順1完了 (6m)`）
- 手順のチェックは、ユーザーが結果を確かめてから付ける。AI が「できた」と思っただけでは付けない
- 作業中に知ったことや、引っかかったことは「気づいたこと」に足す
- コミットはしない。`report` スキルがテーマのディレクトリごとコミットして push する

### 4. テーマを終える

- 完了条件を満たしたら、時間の記録に「完了」の行を足し、`$dojo:report` で振り返るよう案内する
